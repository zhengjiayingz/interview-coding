# 讲解提纲（2026-08-07）

控制口述约 **8～12 分钟**。演示前先 `npm run dev`，浏览器开着备用。

---

## 1. 需求理解（约 1 分钟）

「这是一个通用的学习培训申请：

- 课程支持**线上 / 线下**；线下要选**地点 + 场次**，地点有**人数上限**
- 课程用 **mock**，不做课程后台
- 报名分步：个人信息 → 培训详情（含扩展字段）→ **预览回改** → 提交
- **开课前一天之前**可改部分报名信息
- 特殊活动字段用 **schema** 挂在详情步，组件可复用
- 另有 **ECharts 统计页**；**Vitest** 覆盖领域规则和关键组件

补充字段我放在设计说明里：邮箱、工号、须知同意、报名状态与时间戳等。」

---

## 2. 项目结构（约 2 分钟）

打开目录口述：

| 目录 | 职责 |
|------|------|
| `src/routes/` | 页面：课程列表、报名向导、我的报名、报表 |
| `src/lib/domain/` | **业务规则**（校验、名额、可编辑窗口、提交闸门） |
| `src/lib/components/` | 可复用 UI：Stepper、DynamicForm、VenueSessionPicker、PreviewPanel |
| `src/lib/stores/` | 报名列表 + `localStorage` |
| `src/lib/mock/` | 课程与报表假数据 |
| `src/tests/` + `*.svelte.spec.ts` | 单测 |

**一句话：** 页面管交互，domain 管「允不允许」，store 管「存哪里」。

---

## 3. 演示路径（约 3 分钟）

按这个顺序点，边点边说：

1. **课程列表** → 进「客户服务沟通技巧（线下）」
2. 填个人信息 → 下一步（空提交会被拦住）
3. 选地点/场次，看**剩余名额**；填 T 恤、勾须知 → 预览
4. 预览点「修改此步」跳回 → 再进预览 → **提交**
5. **我的报名**看到记录 → 详情里改电话/换场次 → **保存**
6. （可选）名额满时详情步「下一步」禁用 / 提交报「名额已满」
7. **统计报表**看 ECharts

线上课可快速带一句：不展示地点选择。

## 4. 实现细节 5 点（约 4 分钟，每点约 30～40 秒）

### （1）规则为什么放 domain？

打开 `validate.ts` / `capacity.ts` / `editWindow.ts`。

「校验、名额、可编辑窗口是纯函数，不依赖 DOM。报名页和详情页共用 `assertReadyToSubmit`，单测也好写，避免规则复制到两个页面。」

### （2）特殊活动字段怎么扩展？

打开 `mock/courses.ts` 的 `extraFieldSchema` + `DynamicForm.svelte`。

「详情步用 schema 渲染。新活动只要改课程 mock 加字段定义，不用新写一页表单——对应题面第 5 点。」

### （3）名额怎么算、怎么防超卖？

打开 `capacity.ts`。

「余量 = 场次容量 − 同课程同地点同场次已提交数。草稿不占名额。修改自己报名时传 `excludeEnrollmentId`，避免把自己算进去。详情步剩余为 0 时禁用下一步；提交前再 `assertCanBook` 一道。」

### （4）开课前一天可编辑？

打开 `editWindow.ts`。

「`editableUntil = startAt - 1 天`；`canEdit` 要求 `now < editableUntil`。详情页据此切换表单 / 只读。」

### （5）为什么 localStorage + store 够用？

打开 `applications.ts`。

「题面允许 mock、无后端。`writable` store 跨页共享，`browser` 判断后读写 localStorage。刷新不丢。上真后端时把 persist 换成 API 即可，domain 规则可复用。」

## 5. 已知限制（约 1 分钟）

- 无登录、无真实后端；报表目前以 mock 为主（可说明后续可汇合 store）
- 不做课程管理（题面明确）
- 组件测用 **happy-dom + Testing Library**，不用 Playwright（更轻）
- hybrid 模式校验已覆盖，演示 mock 以 online/offline 为主

## 6. 备用问答

| 可能被问 | 答法 |
|----------|------|
| 和 React 比为什么 SvelteKit？ | 题面指定；文件系统路由类似 Next |
| 测试测了什么？ | domain：校验/名额/编辑窗/提交闸门；组件：Stepper、DynamicForm、PreviewPanel |
| 并发两个人抢最后一个名额？ | 前端 mock 只能乐观校验；真系统要服务端事务/锁 |
| 为什么不用 Redux？ | 单用户本地报名，store 足够；过度设计 |
